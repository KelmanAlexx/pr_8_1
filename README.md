# Auto-Updater (C# / .NET 10)

Консольная утилита для проверки и установки обновлений другой программы.

## Возможности

- чтение локальной конфигурации `updater.json`;
- загрузка манифеста обновления по HTTPS;
- сравнение версий по SemVer 2.0.0, включая предварительные версии (`alpha`, `beta`, `rc`) и метаданные сборки;
- скачивание ZIP-архива обновления;
- проверка SHA-256 до распаковки;
- безопасная распаковка с проверкой путей внутри ZIP;
- резервное сохранение предыдущей папки программы;
- попытка автоматического отката, если установка завершилась ошибкой;
- ограничение размера загружаемого архива — 500 МБ.

## 1. Настройка

Откройте `updater.json` и укажите:

- `ManifestUrl` — HTTPS-адрес JSON-манифеста на сервере;
- `CurrentVersion` — текущую версию установленной программы;
- `TargetDirectory` — папку программы, которую нужно обновлять. Относительный путь считается от папки, где находится Auto-Updater.

Пример:

```json
{
  "ManifestUrl": "https://example.com/updates/update.json",
  "CurrentVersion": "1.0.0",
  "TargetDirectory": "./MyApplication"
}
```

## 2. Формат манифеста на сервере

Сервер должен отдавать по адресу `ManifestUrl` JSON следующего вида:

```json
{
  "Version": "1.1.0",
  "DownloadUrl": "https://example.com/updates/MyApplication-1.1.0.zip",
  "Sha256": "сюда_нужно_вставить_64_символа_SHA256",
  "ReleaseNotes": "Исправлены ошибки и добавлены новые функции."
}
```

`DownloadUrl` должен вести на ZIP-архив с новой версией программы. Внутри архива должны находиться сами файлы программы, а не дополнительная внешняя папка.

Например, правильное содержимое архива:

```text
MyApplication-1.1.0.zip
├── MyApplication.exe
├── MyApplication.dll
├── appsettings.json
└── другие файлы программы
```

## 3. Получение SHA-256 архива

После создания ZIP-архива вычислите его SHA-256.

**Windows PowerShell:**

```powershell
Get-FileHash .\MyApplication-1.1.0.zip -Algorithm SHA256
```

**Linux:**

```bash
sha256sum MyApplication-1.1.0.zip
```

Полученное значение вставьте в поле `Sha256` манифеста. Хеш должен относиться именно к ZIP-файлу, который скачивает утилита.

## 4. Примеры сравнения SemVer

В программе учитываются основные правила SemVer 2.0.0:

| Сравнение | Результат |
|---|---|
| `1.4.0` и `1.3.9` | `1.4.0` новее |
| `2.0.0-beta.2` и `2.0.0-beta.10` | `beta.10` новее |
| `2.0.0-rc.1` и `2.0.0` | обычная версия новее |
| `1.0.0+build.1` и `1.0.0+build.2` | версии равны по приоритету |

## 5. Запуск

Для сборки проекта требуется установленный .NET 10 SDK.

```bash
dotnet restore
dotnet build
dotnet run
```

При запуске без аргументов появится меню:

```text
====================================
          AUTO-UPDATER
====================================
1. Проверить наличие обновлений
2. Проверить и установить обновление
0. Выход
Выберите действие:
```

Также доступны команды:

```bash
dotnet run -- check
dotnet run -- update
```

Первая команда только проверяет версию, вторая устанавливает обновление, если версия на сервере новее.

## 6. Как выполняется обновление

1. Утилита загружает JSON-манифест.
2. Проверяет корректность версии, URL и SHA-256.
3. Сравнивает текущую версию с версией в манифесте.
4. Если обновление доступно, скачивает ZIP во временную папку.
5. Вычисляет SHA-256 скачанного архива и сравнивает его с манифестом.
6. Только при совпадении хеша распаковывает архив во временную папку.
7. Переименовывает старую папку программы в резервную копию.
8. Перемещает новые файлы на место программы и записывает новую версию в `updater.json`.
9. При ошибке пытается удалить новую папку и вернуть резервную копию.

Резервная копия сохраняется рядом с папкой программы под именем вида `MyApplication.backup-20261105-094000-a1b2c3`. Она не удаляется автоматически.

## 7. Важные замечания

- Обновляемая программа должна быть закрыта перед установкой. Сам Auto-Updater должен находиться вне папки, которую он обновляет.
- Для загрузки используются HTTPS-ссылки. Это защищает передачу данных, а SHA-256 дополнительно проверяет целостность скачанного архива.
- SHA-256 подтверждает совпадение файла с хешем из манифеста, но сам по себе не доказывает, кто создал обновление. Для реального распространения обновлений манифест и ZIP следует размещать на доверенном сервере, а при повышенных требованиях дополнительно использовать цифровую подпись.
- Утилита заменяет содержимое папки целевой программы целиком. Пользовательские данные, которые хранятся внутри этой папки, нужно предварительно вынести в отдельное место или отдельно включить в механизм миграции.
